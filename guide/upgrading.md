# Upgrading

Upgrade the CLI and module together, regenerate the code, update the agent instructions and run the checks. Release-specific changes may also require edits to application and project files.

## Upgrade a project

Read the sections of the [changelog](../CHANGELOG.md) between your release and the new one, and the release sections below. Then run these steps in the module root.

1. Install the new CLI and check its version:

   ```sh
   go install github.com/romshark/datapages/cmd/datapages@latest
   datapages version
   ```

2. Update the module. `go get` also raises the requirements that Datapages depends on, such as `github.com/a-h/templ`:

   ```sh
   go get github.com/romshark/datapages@latest
   go mod tidy
   ```

3. Install the templ CLI of the templ version that `go.mod` now requires. `go list -m github.com/a-h/templ` prints it:

   ```sh
   go list -m github.com/a-h/templ
   go install github.com/a-h/templ/cmd/templ@v0.3.1100
   ```

4. Regenerate the code. Code generated by an older release may not compile with the new runtime, with errors such as `undefined: dpsse.New` in `app_gen.go`, until `datapages gen` replaces it:

   ```sh
   templ generate
   datapages gen
   ```

5. Update the instructions for coding agents to the new release, as [AI agents](ai-agents.md) describes. `init` keeps a copy of every file you edited as `<name>.bak`:

   ```sh
   datapages init -n
   ```

6. In `.github/workflows/ci.yml`, change the versions in the `go install github.com/romshark/datapages/cmd/datapages@` and `go install github.com/a-h/templ/cmd/templ@` steps to the versions in `go.mod`. `init` does not rewrite the workflow. With the old versions, CI fails with `go.mod requires github.com/romshark/datapages ... but you are running ...` or `templ generate produced uncommitted changes`.

7. If the app uses the offline module, increase `offline.Config.WorkerVersion`. The browsers then install the worker of the new release and delete the caches of the old one. See [Offline and shims](offline.md).

8. Check the application:

   ```sh
   datapages lint
   go build ./...
   go test ./...
   ```

Then deploy the new build.

### What the CLI checks

A release of the CLI compares its version with the `github.com/romshark/datapages` requirement in `go.mod`. A CLI built from source skips these checks.

- When `go.mod` requires a newer release than the CLI, `datapages gen` and `datapages lint` fail and print the command that installs the matching CLI:

  ```text
  error: go.mod requires github.com/romshark/datapages v0.11.0 but you are running v0.10.1
    run: go install github.com/romshark/datapages/cmd/datapages@v0.11.0
  ```

- When the CLI is newer, `datapages gen` raises the requirement to the version of the CLI and runs `go mod tidy`. Without step 2, the first run can fail with `go: updates to go.mod needed` while it loads the app package. The second run succeeds.
- While the agent instructions come from another release, `datapages gen` prints:

  ```text
  Agent instructions differ from this CLI; run `datapages init -n` to update them (edits are backed up).
  ```

- `datapages watch` checks GitHub for a newer release when it starts and prints `update available:` with the `go install` command when there is one.

[CLI](cli.md) describes these checks in detail.

## Version policy

Datapages is in beta and ready for production use. Its APIs can still change in a release. The public API includes the root `datapages` package, packages under `modules/` and generated packages such as `href` and `action`. The changelog lists each incompatible change under Changed or Removed and gives the required steps.

Packages under `runtime/` serve generated code and may change in any release. `datapages gen` updates their callers. The CLI rejects imports of these packages from application code.

Only the latest release receives security fixes, as [SECURITY.md](../SECURITY.md) states. Each Security entry of the changelog names the affected releases and the steps to take, which are usually to upgrade, run `datapages gen` and deploy.

## Upgrade to the next release

These changes are on the main branch and listed under Unreleased in the changelog.

### Application model

`datapages gen` and `datapages lint` reject these declarations. Fix them before you regenerate.

- Remove `{$}` from the route of a page that has actions, `OnXXX` handlers, `StreamOpen`, `StreamClose` or `State[T]`, as `// PageUser is /user/{name}`. The page keeps its URL. With `{$}` the CLI reports `page route ending in {$} cannot have actions` for an action and `page route ending in {$} cannot have a stream` for the others. See [Pages and routes](pages.md).
- Rename a method of `App` whose name is `GET` or `QUERY` followed by an uppercase letter, such as `GETStats`, when it is a helper and not an action. The CLI reads it as an action and reports `missing the *http.Request parameter in App.GETStats`. See [Actions](actions.md).
- Move page and action routes out of the URL prefix of the static files, such as `/static/`. Otherwise the CLI reports `conflicting route: ... the assets URL prefix serves "GET /static/"`. Before, asset requests below such a route reached the handler instead of the files. See [Static assets](assets.md).
- Remove imports of packages under `github.com/romshark/datapages/runtime` from the application, test files included. Use the `datapages` package or the generated packages. Otherwise the CLI reports `application code must not import github.com/romshark/datapages/runtime/...`.
- Name each `OnXXX` handler after its event, `On` followed by the event name without `Event`, as `OnMessageSent` for `EventMessageSent`. Otherwise the CLI reports `event handler must be named after its event`. Before, such a handler could hide an embedded one, and the generated code did not compile. See [Events](events.md).
- Rename a query tag that contains a character other than ASCII letters, digits, `-`, `.`, `_` and `~`, as `query:"q_a"` for `query:"q&a"`. Before, the handler read an empty value or the action expression failed in the browser. See [`Query`](../SPECIFICATION.md#parameter-datapagesquerystruct-).
- Move `GET` and actions off [stream embeds](../SPECIFICATION.md#stream-embeds). Write `GET` on each page and share its code through a helper. Move an action to 1 page, or to `*App` when several pages call it. A stream embed keeps its `OnXXX` handlers, `StreamOpen` and `StreamClose`. Otherwise the CLI reports `unsupported method on stream embed`.
- Pass the directory of the app package to `datapages watch --app`, as `--app app/frontend`. `--app frontend` fails with `no app package in "frontend"`. Update scripts and Makefiles that pass the flag. See [Multiple applications](multiple-applications.md).

### Generated code and runtime

- Install Go 1.27.3 or later first where `GOTOOLCHAIN=local` is set. `go get` raises the `go` line of `go.mod` to 1.27.3.
- Install templ v0.3.1100 and run `templ generate`, as steps 3 and 4 do. A `*_templ.go` file written by an earlier templ fails to compile with `undefined: templ.ResolveAttributeValue` or `undefined: templ.JoinURLErrs`.
- Run `datapages gen` before you build, as step 4 does. The generated code no longer uses `github.com/starfederation/datastar-go`, and older generated code does not compile with the new runtime. `go mod tidy` then drops `datastar-go`, `github.com/CAFxX/httpcompression` and `github.com/valyala/bytebufferpool` unless the application imports them.
- Submit forms that post to an `App` action that takes `datapages.PageCacheWriter` through a Datastar action. A plain form submission to such an action now gets `406 Not Acceptable`. Before, a redirect from the action dropped its cache writes, such as `ClearAll`. See [Templates and forms](templates.md).
- Pass `datapages.WithDatastarJS` a URL that is valid according to RFC 3986. Otherwise `datapages.NewServer` fails with `applying server option: WithDatastarJS: URL contains ' ', which RFC 3986 does not allow`.
- Spell asset URLs exactly like their file names. `/static/App.js` for `app.js` now answers 404 on every system and in dev mode. Before, Windows and macOS served it. See [Static assets](assets.md).
- In a custom `messaging.Broker`, deliver messages in the order they were published, whatever their subjects, and close the channel of a subscription when it can no longer receive messages, as after its connection closed. Otherwise pages handle events out of order, or keep a stream that receives nothing. [`messaging.go`](../modules/messaging/messaging.go) states the contract.
- Responses of pages and actions are now compressed by default. Behind a proxy that edits response bodies, such as nginx with `sub_filter`, add `datapages.WithNoResponseCompression()` or have the proxy send `Accept-Encoding: ""`. Send pages that combine a secret with attacker-controlled input with `Cache-Control: private, no-transform`. Otherwise the size of the compressed response can reveal the secret. See [Response Compression](../SPECIFICATION.md#response-compression) and [Security](security.md).
- Static assets are now compressed by default. Keep asset files unchanged while the server runs. Serve a file that changes through a GET action that returns `datapages.File`, or add `datapages.WithNoAssetsCompression()` and set `AssetsCacheConfig.DisableETag`. Otherwise a changed file of `datapages.WithAssetsFS` keeps its old `ETag`, and its compressed copy can keep the old content, until a restart. See [Changing Assets](../SPECIFICATION.md#changing-assets).

### Project files

These files belong to the project, and `datapages init` does not rewrite them. Change a project created by v0.10.1 or earlier by hand.

- Set the templ version in `.github/workflows/ci.yml` to the one in `go.mod`, as step 6 does. A new project uses templ v0.3.1100, and a project created earlier installs v0.3.1020 in its workflow.
- Add `syscall.SIGTERM` to the `signal.NotifyContext` call of `cmd/server/main.go`, as `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)`. Otherwise Docker, Kubernetes and systemd, which stop a process with SIGTERM, end the server without waiting for requests, SSE streams and `StreamClose` hooks. See [`App`](../SPECIFICATION.md#app).
- If the app package declares static files, check that `cmd/server/main.go` passes them with `datapages.WithAssets(app.StaticFS, false)`. Otherwise every asset URL answers 404. See [Static assets](assets.md).
- In `.github/workflows/ci.yml`, move the `Checkout repository` step above `Install Go`, which lets `actions/setup-go` restore its cache.
- In the `gen` target of `Makefile`, add `go run github.com/a-h/templ/cmd/templ@v0.3.1100 generate` after `datapages gen`. Otherwise `make gen` leaves `*_templ.go` stale after a `.templ` change, and CI fails on the uncommitted diff.
- Run `datapages init -n`, as step 5 does. The new instructions tell agents to put JavaScript that Datastar expressions cannot hold, such as a library, in a Web Component.

## Upgrade to v0.10.1

- Delete the `AGENTS.md` that v0.10.0 wrote before you run `datapages init -n`, and copy your own additions to it first. It ends without a stamp, and `init` leaves such a file alone as your own and prints `Left AGENTS.md alone: it has no datapages stamp. Delete it to have init write it.` Agents then keep reading the instructions of v0.10.0.
